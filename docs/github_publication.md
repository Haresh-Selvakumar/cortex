# GitHub publication preparation — 14 October 2026

This repository extends `public_submission_v1` for publication. **Public hosting
is not deployed; there is no public tryout URL.** A GitHub repository is a source
distribution, not a running application. Docker/Compose recipes remain unvalidated.

Authorised publication target: [Haresh-Selvakumar/cortex](https://github.com/Haresh-Selvakumar/cortex),
branch `main`. Source publication is a real GitHub operation; the application's
Git-tool workflow remains validated against disposable local remotes only.

## Start from a checkout

Python 3.10+ is required; validation used Windows/Python 3.13.7. There are no
third-party runtime dependencies. From the repository directory:

```powershell
git clone --config core.autocrlf=false https://github.com/Haresh-Selvakumar/cortex.git
cd cortex
python -m cortex examples/supplier_task.json
python -m unittest discover -s tests -q
python -m cortex web --state-dir .cortex/local-browser
```

Open the printed local owner URL privately. In a separate terminal:

```powershell
python -m cortex web-reminders --state-dir .cortex/local-browser --seconds 86400
```

Supplier execution is deterministic: Beta, total 11500, four **synthetic work
units**, zero model calls. Drafting needs a configured, reachable provider.
Configuration examples contain localhost/reserved endpoints and credential
environment-variable names; supply actual credentials privately. `.env.example`
is documentation, not a loaded credential file. Keep real config in an ignored
file. Model/pricing declarations are configuration, not guarantees.

For reproducible wheel builds, install `requirements-build.txt`, then follow
[the packaging and hosting guide](public_submission_v1.md). Prebuilt wheels and
checkpoint ZIPs are deliberately excluded from this Git repository. A public
host still requires HTTPS ingress, dedicated persistent storage, supervised web
and scheduler processes, and an optional permitted private model backend.

## Public files and local exclusions

`publication-manifest.json` at the project root lists the exact reviewed file
set with SHA-256 checksums (excluding itself to avoid a circular hash). It is
generated by `python scripts/publication_audit.py --write-manifest`. After staging,
`python scripts/publication_audit.py --staged` checks the index against that list.
The scanner reports only finding categories/locations, never matched secrets.
It is a heuristic review aid, not a guarantee of secret detection.

Public: source/UI/defaults, original tests, synthetic development fixtures,
examples, scripts, deployment recipes, setup/checkpoint guides, five reviewed
screenshots, thumbnail, demo script and project description.

Local-only: `runs/`, `snapshots/`, `releases/`, `.cortex/`, `.test_tmp/`, SQLite
databases, raw traces/logs, actual configurations, credentials, reserved held-out
wording, original experiment/validation logs, and screenshot
`06-readback-evidence.jpg` (private local path/session identifier). The originals
and their frozen checkpoints are retained without publication. The public asset
manifest records the screenshot exclusion; its former entry and all original
assets remain in the local frozen checkpoint. No screenshot was visually altered.

Historical guides may name local-only evidence paths. Those references document
the original development record; the private artifacts are not available in a
fresh clone. Both frozen comparison scripts are preserved unchanged and require
the owner's original local checkpoint ZIPs. Ordinary unit/regression tests and
synthetic development fixtures run without private evidence. The held-out wording
was not evaluated and is not distributed. Historical wheel hashes describe the
frozen release, not newly edited publication documentation.

The clean public-copy check identified one currency regression test loading two
private run files. Its two rejection assertions are retained, now using labelled
synthetic drafts in `tests/fixtures/currency_rejections.json`. The original test
and raw responses remain in the frozen checkpoint. These public fixtures are not
claimed as live model evidence.

Publication validation: compilation and **260 tests passed** from an exported
copy of exactly the public files (254 existing tests plus six publication checks).
The supplier command completed as Beta/11500 with four synthetic units and zero
model calls. The review verified 700 original source/test/evidence/asset files
unchanged, including every original Cortex module, raw run and checkpoint; the
one fixture-path test adaptation is described above. Private scans covered 636
files and 11,091 entries including nested archive contents. The final public scan
reported no pattern findings. This is heuristic screening plus manual image
inspection, not proof that every possible secret format is detectable. No live
model/tool demonstration was repeated to prepare this commit.

Credential-pattern scans cover the proposed source/config/docs/fixtures and local
trace/archive text, including nested ZIP members without extraction. All raw
archive/evidence content is excluded regardless of scan findings. Public images
were inspected visually and checked for metadata; no private readback screenshot
is shipped. Exact environment-secret matches are checked locally without writing
their values. No credential-bearing files or archives should be force-added.

## Commit and remote boundary

The first commit contains only the reviewed manifest. Existing local checkpoints
are not Git history. Use an authenticated Git identity; a repository-scoped GitHub
no-reply author protects the local configured contact email. No license was
selected on the owner's behalf; see `LICENSE_NOTICE.md`.

The clone command preserves original mixed line endings, so source/job hashes and
the byte-level publication manifest remain reproducible. Legacy whitespace and
original source bytes were preserved rather than reformatted for this publication.

Repository creation/publication must use the explicitly authorised GitHub account
and new target. Push `main` with a normal, non-forced push. Verify the remote branch
commit equals the local commit before reporting publication. If creation or push
times out, inspect the remote before retrying. Never upload local archives as
release assets without another privacy review.
